## Scope

Carried in from the 1.0.1 release, which surfaced them:

- **Release-tooling test fixes.** `test_release_tools.py` asserted that the
  checked-in release artifact is always an unbound draft, and hardcoded the release
  version in its manifest tests. The first made `make quality` fail on any release
  commit; the second made it fail on every post-release draft reset. Both are fixed:
  the repo-state guard is now scoped by declared status, and the version is derived
  from the artifact. This is why the 1.0.1 release commit shipped with two known
  failing tests.
- **Stop shipping test code in the runtime image — done.** `base.Dockerfile` now copies
  only `ai-review/tests/fixtures`, which is all preflight resolves paths from, and the
  build-time in-image suite is removed. Both preflights instead bind-mount the
  checkout's tests into the built image, which still proves "this exact image passes the
  suite" and proves it against the *current* tests rather than whatever was frozen into
  the layers. A production image that processes untrusted diffs and model output no
  longer carries test code, and a change to test *code* no longer alters image
  identity. Fixtures are the exception and still ship, because the reviewer preflight
  runs `--read-only` with no mount and resolves its diff and repo from them; a fixture
  change therefore does alter the image digest and stays part of the release binding.
  The GitLab image-build template is removed entirely (see below), so the only image
  build that remains is the GitHub publish workflow.
- **Removed the GitLab image-build template.** `ai-review/ci/build-images.gitlab-ci.yml`
  built the product images from a GitLab mirror of this repository. No such project
  exists, no current user-facing documentation referenced it, it was not part of the
  hashed release artifact, and it was never executed against a real GitLab instance.
  The historical Phase-2 acceptance record still references it and is retained as
  written, with a superseded-procedure note added rather than its findings edited. Its
  supply-chain guards in `check_supply_chain_pins.py` are removed with it. GitLab remains
  a fully supported *consumer* platform — `review.gitlab-ci.yml` and
  `review-child.gitlab-ci.yml` are unchanged, still hashed in `canonical_templates`, and
  still covered by the live evidence campaign. What is gone is only the ability to build
  the images *from* GitLab; a consumer needing that would write their own pipeline around
  `base.Dockerfile` and `reviewer.Dockerfile`.
- **Tag signing — established.** SSH signing is configured and verified end to end
  (`Good "git" signature`), with signers in `.github/allowed_signers` and the procedure
  documented in
  [release-process.md](../docs/development/release-process.md#tag-signing). Applies from
  `v1.0.2`; `v1.0.0` and `v1.0.1` remain unsigned and are not being retagged.

Also included in this release:

- **Reliable OpenCode structured output.** The adapter now uses OpenCode's
  schema-backed `StructuredOutput` transport through a loopback client, treats only
  answer parts as answer text, rejects ambiguous JSON streams across every adapter,
  and retains redacted raw stdout when parsing fails. A provider-free image preflight
  exercises the complete transport, including its permission negative control.
- **Bounded OpenCode tool reach.** The reviewer explicitly denies external-directory
  access, resolves the packaged CLI and interpreter ahead of ambient `PATH`, and ships
  a checksum-verified ripgrep so search never downloads an unverified executable at
  review time. Image preflights verify the effective permissions and both pinned
  binaries against decoys.
- **Four peer reviewer seats.** `AI_REVIEW_REVIEWERS` selects any roster of Claude,
  Codex, OpenCode, and Cursor while preserving the shipped Claude/Codex/OpenCode
  default. Thresholds are validated against the configured panel and clamped to the
  selected seats without dropping corroboration below two. GitHub scopes
  `CURSOR_API_KEY` to the Cursor matrix job only; Cursor remains disabled by default.
- **Independent review and critique budgets.** Review stages default to 1,800 seconds
  and critiques to 900 seconds, with separate CI ceilings and a capped compatibility
  fallback for older configurations. OpenCode forwards `max` effort unchanged rather
  than rejecting or silently remapping it.
- **Refreshed reviewer toolchain.** The published image pins OpenCode 1.18.12, Claude
  Code 2.1.221, Codex 0.146.0, Cursor Agent 2026.07.23-e383d2b, and ripgrep 15.1.0.

Deferred, deliberately not in 1.0.2:

- **SPEC-42 — whether a human `/ai-review wontfix` may clear the merge gate.** Deferred
  by decision. The current behaviour is unchanged and documented: `wontfix` durably
  dismisses a finding and suppresses re-posting, but consensus keeps counting it as
  blocking and the required check stays red. Reproduced live again at 1.0.1. The only
  escapes remain disabling `merge_gate.enabled` or removing the required check.

**Version decision.** This ships as 1.0.2. The new reviewer roster is opt-in, the
shipped three-seat default and existing per-seat controls are unchanged, and the
remaining product changes are compatible fixes and operational hardening. Removing
test code changes image identity but not the supported runtime interface. The release
therefore keeps the already-reviewed patch target rather than reopening the train as a
minor release.

## Release gates

- Run the scoped campaign against one frozen runtime source `R` and the final
  base/reviewer pair.
- Record only sanitized evidence; keep private consumer coordinates out of the
  public repository. Audit with `scripts/scan_evidence_leaks.py` and record its
  exact scope.
- Activate the release inputs only after every non-waived release-gating record
  binds to the same source and image digests.

## Tagging

The external manifest binds `release_commit` and re-derives the `R..P` diff, so the
tag must point at a commit that satisfies it.

- Tag **`P`** exactly. Do **not** squash-merge the release PR: a squash rewrites `P`
  into a new commit and drops it from `main`'s history, invalidating the manifest.
- If you want the tag on `main`'s tip instead, rebuild and re-validate the manifest
  against the merge commit — this only validates while `main` has not advanced past
  the merge, because `changed_paths` is recomputed from `R..P`.
- Re-run `scripts/check_release_manifest.py` after any change of tag target and
  attach the regenerated manifest, not an earlier copy.
- Write the annotated tag message as a release certificate: `R`, `P`, publication
  run, both digests, evidence summary, registered waivers, known shipped
  limitations, and the external manifest sha256. Compare
  `git show --no-patch v1.0.0`.
