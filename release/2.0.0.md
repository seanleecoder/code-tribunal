## Scope

- **Findings are informational; the merge gate is gone.** A finding surfaces as a
  thread when two independent reviewer identities support it across review and
  critique. Severity is an impact label only. The `gate` (GitHub) and
  `ai_review_gate` (GitLab) jobs, their schemas, CLI, and `out/gate/` artifact are
  removed. `post` is the terminal job and fails only on a publication failure.
- **New configuration contract, `review_config.v3`.** It has one roster of three or
  four seats selected with `AI_REVIEW_REVIEWERS`, fixed trusted adapter, credential,
  and endpoint routes, and independent review and critique timeouts. Retired
  overrides are rejected with migration guidance. A `review_config.v1` document,
  which every 1.x release shipped, is rejected once with the complete list of
  removed keys.
- **New artifact and body formats.** `consensus.v2` replaces `consensus.v1`.
  `render-body.v4` replaces `render-body.v3` with a `Support:` footer, and
  existing threads receive one cosmetic update. `code_tribunal.release_inputs.v2`
  drops the redundant `hashes` object.
- **Cursor is a peer seat.** It is still off in the default roster because of its
  separate credential and egress path. On GitHub it receives `CURSOR_API_KEY` only
  when `AI_REVIEW_REVIEWERS` names it.
- **GitLab matrix jobs.** Review and critique are one four-seat parallel matrix
  apiece.
- **Refreshed runtime.** The image pins Claude Code 2.1.280, Codex 0.156.1,
  OpenCode 1.18.32, and Cursor Agent 2026.09.18-9a7762b, on Python 3.14 and
  Debian Trixie. The reviewer image no longer ships Node, npm, or npx.
- **Candidate Canary.** A protected, manually dispatched four-seat campaign on both
  demo consumers now gates promotion of a candidate image pair.
- **Compatibility debt retired.** COMPAT-003 (the split GitLab token wording) is
  removed. COMPAT-001 and COMPAT-005 are retargeted to the first release after
  2.0.0, and COMPAT-002 now covers `review_config.v1`.

**Version decision.** 2.0.0 is a semver major. Removing the gate checks, the
`review_config.v3`, `consensus.v2`, and `render-body.v4` contracts, and the
rejected variables all break 1.0.x consumers that do not migrate.

## Migration

Follow [Upgrade from 1.0.x to 2.0](../docs/operations.md#upgrade-from-10x-to-20).
In short:

1. Remove the required `gate` check from branch protection or rulesets first.
2. Delete the rejected `AI_REVIEW_*_ENABLED`, `AI_REVIEW_MERGE_GATE_ENABLED`, and
   `AI_REVIEW_STATE_BACKEND` variables.
3. Select at least three seats with `AI_REVIEW_REVIEWERS`.
4. Migrate custom configuration to `review_config.v3`.
5. Update the template and both images together.
6. Move `consensus.json` consumers to `consensus.v2`.

The CHANGELOG Migration table lists every retired surface.

## Release gates

- Run the scoped campaign against one frozen runtime source `R` and the final
  base/reviewer pair.
- Record only sanitized evidence; keep private consumer coordinates out of the
  public repository. Audit with `scripts/scan_evidence_leaks.py` and record its
  exact scope.
- Activate the release inputs only after every non-waived release-gating record
  binds to the same source and image digests.
- `R..P` may touch only the release-path allowlist, so every runtime, script, and
  non-evidence documentation change lands before `R` is frozen.

## Tagging

The external manifest binds `release_commit` and re-derives the `R..P` diff, so the
tag must point at a commit that satisfies it.

- Tag **`P`** exactly. Do **not** squash-merge the release PR: a squash rewrites `P`
  into a new commit and drops it from `main`'s history, invalidating the manifest.
- Re-run `scripts/check_release_manifest.py` after any change of tag target and
  attach the regenerated manifest, not an earlier copy.
- Write the SSH-signed annotated tag message as a release certificate: `R`, `P`,
  publication run, both digests, evidence summary, registered waivers, known
  shipped limitations, and the external manifest sha256.

## Carried known limitations

- GitLab does not enforce the trusted image or trusted composition inside the
  consumer pipeline; containment relies on protected credential withholding plus
  the out-of-band trust auditor.
- Network egress is not enforced at the container or runner boundary.
- "Credential isolated" is claimable only in the recorded hardened-child,
  unprotected-ref topology. GitLab forks remain untested.
- Cursor is off in the default roster. The canary exercises it with `auto`, but
  nothing verifies that the pinned CLI honours its deny policy at runtime.
