# Code Tribunal 1.0.1 (draft)

> These are working notes for the next patch release. They are not release
> evidence or a release certificate until `v1.0.1` is tagged and the external
> manifest validates against the final release inputs.

## Release identity

- Target release: `1.0.1`
- Target tag: `v1.0.1`
- Release inputs: `release/release-inputs.json`, currently `status: draft`
- Runtime source and image digests: unset until the 1.0.1 release candidate is
  frozen and published

Release versions are `MAJOR.MINOR.PATCH` with an optional prerelease suffix such
as `-rc.1`; build metadata is not supported. The release validator derives the
required notes path from this value (`release/<version>.md`).

## Scope

This patch release carries the post-1.0.0 fixes and release-readiness work. The
Cursor CLI remains an opt-in substitute reviewer with a separate credential and
egress path. Completing SPEC-21 acceptance is required to ship 1.0.1; the
historical 1.0.0 Cursor runs do not certify this release.

## 1.0.1 release gates

- Run the current evidence matrix against one frozen runtime source and final
  base/reviewer image pair.
- Complete the canonical [SPEC-21 Cursor acceptance checklist](../docs/improvement-specs/spec-21-cursor-cli-reviewer.md#101-closure-checklist)
  before shipping, including the explicit ask-mode product decision. If the
  chosen contract requires Cursor-backed blocking findings, include the
  blocking fixture and verify that a required check genuinely blocks.
- Record only sanitized evidence and keep private consumer coordinates out of
  the public repository.
- Activate the release inputs only after all release-gating records bind to the
  same source and image digests.

## Finalization

After every required gate passes and the release commit and tag exist, build and
validate the external manifest with the 1.0.1 coordinates, publish the
manifest/checksum, and update this file from draft notes to final release notes
in the release commit.
